============================================================
1. EMAIL PROTOCOLS
============================================================
SMTP = Simple Mail Transfer Protocol
- Used to SEND/relay email.
- Runs over TCP.
- Traditional server-to-server SMTP port: 25.

POP3 = Post Office Protocol version 3
- Used by a client to RECEIVE/retrieve email from a mail server.
- Traditional port: TCP 110.

Simple memory:
SMTP = Send
POP3 = Receive

============================================================
2. PACKET TRACER EMAIL SERVER CONFIGURATION
============================================================
1. Click Mail Server.
2. Services -> EMAIL.
3. Turn SMTP On.
4. Turn POP3 On.
5. Set domain, e.g. fast.com.
6. Create users.

Manual example users:
cs  / 123
ee  / 456
bba / 789

============================================================

============================================================

User Name: cs

Example for BBA:

Username: bba
Password: 789
Incoming/Outgoing: same mail-server IP

Send example:
From bba@fast.com
To cs@fast.com
Subject: Test
Message: Hello CS

Then on CS client click Receive.

============================================================
4. EMAIL TROUBLESHOOTING
============================================================
If "Connection timeout":
1. Ping the mail server IP from the PC.
2. Check PC default gateway.
3. Check server default gateway.
4. Ensure SMTP and POP3 are On.
5. Check username/password/domain.
6. Check incoming/outgoing server IP.

If sending works but receiving fails:
SMTP side may be working; check POP3, credentials and client-to-server reachability.

============================================================
6. FTP CONCEPT
============================================================
FTP = File Transfer Protocol.
- Transfers files between client and server.
- Uses TCP.
- Control connection traditionally uses port 21.
- Traditional active-mode data connection uses port 20 from server side.

FTP can use active or passive data connection behavior.
FTP credentials/data are not inherently protected like SSH-based transfer; secure alternatives include FTPS or SFTP.

============================================================

============================================================

8. CONNECT TO FTP SERVER
============================================================
On PC:
Desktop -> Command Prompt

Command:
ftp <server-IP>

Example:

Then enter:
Username: Fast
Password: 1234

Successful login shows an ftp> prompt.

============================================================
9. CREATE AND UPLOAD A FILE
============================================================
Packet Tracer method:
PC -> Desktop -> Text Editor
Create/save a file named:
test.bin

Then connect via FTP and run:
put test.bin

Meaning:
put = upload local PC file to FTP server.

List server files:
dir

============================================================
10. VERIFY/DOWNLOAD FROM ANOTHER PC
============================================================
On second PC:
ftp <server-IP>
login

dir

If test.bin is listed, the upload exists.

To download it to the second PC:
get test.bin

Then:
quit

Open PC -> Desktop -> Text Editor and open test.bin to read it.

Memory:
put = PC -> Server
get = Server -> PC
dir = list server files

13. WIRESHARK INTRODUCTION
============================================================
Wireshark is a packet analyzer used for:
- Network troubleshooting
- Protocol analysis
- Education
- Investigating network conversations

Basic workflow:
1. Open Wireshark.
2. Choose the network interface.
3. Start capture.
4. Generate traffic.
5. Apply a display filter.

Example filter:
tcp

This displays TCP packets only.

Useful safe practice filters:
http
 tcp
 dns

============================================================
14. HTTP PACKET ANALYSIS IDEA
============================================================
When analyzing HTTP traffic, you can inspect:
- Source/destination IP
- Source/destination port
- TCP handshake
- HTTP method such as GET/POST
- HTTP headers
- Response codes

HTTP is not encrypted; HTTPS encrypts application data using TLS, so packet contents are not readable in the same way.
